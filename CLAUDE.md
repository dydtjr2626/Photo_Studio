# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"Photo Studio": a browser-only image-card editor. Users add photos (PNG/JPEG), edit them (adjust, crop, brush, touch-retouch), overlay text, pick a background template and aspect ratio (1:1 / 4:5 / 9:16 / free), then export a PNG/JPEG. UI text and code comments are in Korean — keep that convention.

No build step, no dependencies, no package.json, no tests, no linter, not a git repo.

## Running

```
node server.js     # static server → http://localhost:8000
```

`server.js` only serves `.html/.js/.css/.jpg/.png` from its own directory (anything else → 404; so `.json` etc. cannot be fetched). If you add a new asset type, update both the `types` map and the extension regex in `server.js`.

## Files

- `index.html` — all markup (CSS moved out, see UI 개편 below); element IDs are looked up directly by `app.js` via `$('id')`, so renaming an ID breaks the script. Make sure line 1 is `<!doctype html>` (a stray character before it puts the page in quirks mode).
- `app.js` — all logic, one plain script (no modules), organized in banner-comment sections.
- `server.js` — static file server.
- Images: `공포.jpg`, `사랑스러움.jpg`, `생일.png` (templates), `logo.png` (512×512, currently unused — the top "Photo Studio" logo banner was removed).
- Docs: `확인방법.md` (short check guide for template JSON / finished images), `출처기록표.md` (image provenance table; `(작성 필요)` cells are for the user to fill in).

## Architecture (`app.js`)

- **Single render engine for preview and export.** `render(canvas, state, engine, fast)` draws background template → photos (clipped to an inner black-frame inset) → text items. `paint()` renders into the offscreen canvas `off`, then copies to the visible `#cv`. `exportAs()` crops `off` to the frame interior and round-trips the encoded blob, diffing it against the preview pixels (`diff`, `hasMetadata`) and showing the result in the "cmp" box. Never draw preview differently from export; that check is a feature.
- **Fixed output resolution per ratio** (`RATIOS`: 1080×1080 / 1080×1350 / 1080×1920, plus a mutable `free` entry: width 1080, aspect clamped 0.5–2.2 via `FREE_MIN/MAX`). In free mode the black frame's edges/corners are draggable (`.fh` handles in `#layer`, CSS width kept in `freeW`, `#cv.free` has no max-height). In free mode the "가운데 기준" toggle (`#freeCenter`, `freeCenter`, default on; Alt inverts while dragging) makes the vertical drag symmetric: height changes by 2×(pointer delta) (width always does, since the stage is centered) and each move measures how far the canvas center (viewport coordinates) drifted from where the drag started and cancels it with `window.scrollBy` (`paint()` is called synchronously so the layout is up to date; when the page is already at scrollY 0 and the canvas shrinks, the missing scroll is made up with a temporary `margin-top` on `.stage` (consumed first when it grows again, cleared when leaving free mode). All item positions/sizes are percentages (x, y, s as % of canvas), not pixels.
- **State**: `state = {items, photos, bg, ratio, sel, editing}`. Text `items` and photos share `state.sel` and a common hit-test/drag path (`hit`, `layer` pointer handlers); `lastBoxes` from the last render drives hit-testing and the selection overlay `#sel` (resize handles for photos only). Selected text shows a dashed blue box, selected photos a persistent box with handles. Text is drawn as solid color with no outline. Text items have `rot` (degrees, clockwise): `drawItem` rotates around the box center and returns `box.rot`; `drawSel` rotates `#sel` with CSS; `hit` inverse-rotates the pointer; tilting is done with the rotation handle `.rh` above the selection box (a solid line ending in a dot, `rotating` state; Shift = 15° steps, snaps near 0/90°, double-click → 0°) for texts, shapes, stickers AND photos/drawings (`photo.rot`); the edge-middle dots (`.hd`, `scaling` state) stretch text/shape non-uniformly via `sx`/`sy`, its corner dots (`scaling.uni`) change `s` proportionally, and the top-right corner is a red × delete button (`.hd.del` → `removeSel()`, no confirmation, undoable) (0.2–5, measured along the text's own rotated axes, glyph distortion is accepted; text may extend past the margin/canvas and get cut off, only its center is kept inside the canvas by dragging; the inline editor textarea gets the same rotate/scale transform; `#resetStretch` resets) ; the "기울기 초기화" button (`#resetRot`) sets it back to 0.
- **Text font/background**: each text item also has `font` (key of `FONTS`: gothic/myeongjo/round/hand/mono — system-installed font stacks, no webfonts, so appearance varies per PC), `bgOn`, `bgColor` and `bgClear` (background transparency 0–100%, default 0 = opaque; only the background gets the alpha). `drawItem` draws a rounded rect behind the text (padding 0.5×/0.25× font size, included in the box/clamp/wrap width; skipped for blank text) and rotates it together with the text. UI: `#fontSel`, `#bgToggle` (single button showing 비적용/적용, default 비적용, click toggles), `#bgc`, `#bga`; all go through `setParam` (`font`, `bgOn`, `bgColor`, `bgClear`). To bundle real font files, add the extension to `server.js` (`types` + regex). `save()` is intentionally a no-op: nothing persists across reload.
- **Text style / shapes / stickers**: text items also carry `op` (글자 불투명도), `b/i/u/st` (굵게 default on / 기울임 / 밑줄 / 취소선 — underline/strike are drawn manually as rects), `align` (left/center/right, relative to the widest line), `ls` (글자 간격, % of font size via `ctx.letterSpacing`, reset to 0px after each item) and `lh` (줄 간격 %). UI in `#styleBox` (`#fmtSeg`, `#alignSeg`, `#opSl`, `#lsSl`, `#lhSl`); everything goes through `setParam`. Items with `shape` (`SHAPES` map of unit-square paths: rect/round/circle/triangle/heart/star/bubble/arrow) are drawn by `drawShape` — size = `s`×3% of width, plus color/`op`/`rot`/`sx`/`sy` like text; `#textOnly` (text-only controls) is hidden for them and dblclick editing skips them. Emoji stickers are just text items from `STICKER_CATS` (13 categories ≈362 emoji: 하트·반짝임, 자연·날씨, 동물, 음식·카페, 소품·취미, 표정·손짓, 운동·게임, 일상·사무, 의상·뷰티, 파티·기념일, 여행·장소, 기호·말풍선, 숫자·글자; category chips `#stickerCats` switch the grid `#stickerRow` via `showStickers`; only widely supported emoji, avoid Unicode 14+ like 🫠/🥹/🫶/🩷 which show as tofu on older Windows). The 도형·스티커 panel (`#shapeRow`, `#stickerRow`) is built in JS.
- **잠금**: `#lockBtn` (dock, enabled when an unlocked photo/drawing is selected) sets `locked` on the selected photo/drawing/text/shape, deselects it and shows a toast. `hit()` still finds locked items but pointerdown never selects/drags them (no editing on dblclick either), and clicking a locked item (pointerdown in `hit()` order) sets `revealedLock` without selecting/moving it; `syncLocks()` (called from `paint()`) shows the unlock button (`.unlockBtn`, padlock icon) only for that revealed item, at the top-right of its visible area, clamped to stay inside the frame; clicking elsewhere, Esc, undo/redo or unlocking hides it. A locked item still captures clicks over its area (locked blank drawings only where they have pixels), so a locked full-frame photo blocks clicks to things below it. The flag is part of `snapDoc`/`docKey`/`restoreDoc` (undoable); duplicates start unlocked. Text and shape items can be locked too (`item.locked`, part of the items JSON in `snapDoc`); their unlock icon sits at the (rotated) top-right corner of the box, and the icon's click handler re-finds the object by id because undo replaces `state.items`.
- **그림 선택 상자**: for blank drawings `drawSel`/`syncLocks` use `selBoxOf()` — the bounding box of non-transparent pixels (`blankBBox`, cached in `p.bbox`: `undefined` = recompute, `null` = empty → falls back to the whole frame; the pen widens it incrementally in `drawSeg`; `endStroke`, `undoPhoto`, reset, `transformPhoto` invalidate it). Hit-testing is still `blankHit` (pixels near the pointer). Corner/edge-handle resizing of a blank drawing scales around the drawing's bbox center (the photo's `x/y` are adjusted so that center stays put); the 크기 slider (`#ps`) does the same via `setPhotoScale()` (note it reads `lastBoxes`, i.e. the previous render, so it needs a render between slider events — `draw()` is rAF-throttled and normally has run). Normal photos scale around the photo center.
- **복사** (formerly 복제): the `#orderRow` bar (`.orderbar`, right under the preview canvas, above the dock) holds the 복사 button `#dupBtn` (Ctrl+J, `duplicateSel`) and the "이전" button `#undoBtn` (global undo = `undoAny()`, same as Ctrl+Z; enabled only when `docHist` or the selected photo's `hist` has something, see `refreshUndo()`; the old per-photo "이전" button `#undoPhoto` was removed) and is shown only while a photo/drawing/text/shape is selected (the 이전 button is always visible) (`syncUI`); the bar keeps its height so the layout does not jump. There is no 앞으로/뒤로 (z-order) UI or shortcut any more (it was removed on request); the draw order is still computed by `drawOrder(state)` (objects may carry a leftover `z`; without `z` photos are below and texts/shapes above, in array order) and `render`/`lastBoxes` follow it.
- **Photo tilt** (`photo.rot`, degrees): `render` rotates the drawn photo about its own center and puts `rot` in the photo box; `hit()` already inverse-rotates by `box.rot`; `selBoxFor()` returns the selection box with its center rotated about the photo center (blank drawings use their bbox), `drawSel` skips frame-clipping for tilted photos; `bboxCenterInfo()` (resize/slider around a drawing's center) accounts for the tilt; `unrotPt()` maps pointer positions back for drawing on a tilted photo; entering crop or liquify resets `rot` to 0 with a toast (their pixel mapping assumes an untilted photo). `rot` is part of `snapDoc`/`docKey`/`restoreDoc`.
- **Photo stretch (side handles)**: on a selected photo the corner dots resize uniformly (`resizing`) while the four edge-middle dots stretch it non-uniformly along its own axes (`scaling.photo`; the picture may be distorted). While dragging `p.dsx/p.dsy` temporarily multiply the drawn size in `render`; on release `bakeStretch(p)` resamples `canvas` and `orig` to the new width/height (≤6000px, via `pushHist` so "이전"/Ctrl+Z undo it) and adjusts `p.scale` so the on-screen size stays the same, then everything else (`blankBBox`, drawing, crop mappings) keeps assuming uniform scale. For blank drawings the stretch is anchored at the drawing's bbox center (`scaling.anchor`; `p.x/p.y` are adjusted live). Repeated stretching resamples the pixels each time (some softness).
- **Photo rotate/flip**: `#rotPhoto` (90° clockwise), `#flipH`, `#flipV` → `transformPhoto` rewrites `canvas`/`orig` pixels after `pushHist`, so they are undone with "이전"/Ctrl+Z like crop and brush.
- **Background color**: `state.bgColor` (default white, `#bgPick` in the template panel) fills the canvas under everything; picking a color clears `state.bg` (single-color background instead of a template).
- **Undo/redo (document level)**: `checkpoint(key)` snapshots (`snapDoc`: items JSON, photo x/y/scale/adj, bgColor, bg, sel) *before* each change — add/delete/duplicate/reorder/drag start/handle start/`setParam`/photo sliders/template pick/arrow keys; same `key` within 800ms is coalesced so a slider drag is one step. `undoAny()` (Ctrl+Z) compares `seq` of the newest `docHist` entry and the selected photo's newest pixel-history snapshot (`pushHist` stamps `seq`) and undoes the more recent; `redoDoc()` is Ctrl+Y / Ctrl+Shift+Z (document history only — pixel undo has no redo). Snapshots that equal the current state are skipped. Arrow keys nudge the selection 0.5% (Shift 2%) when focus is not in a text field/slider.
- **Photoshop-style shortcuts** (one `keydown` handler after `duplicateSel`; Ctrl+Shift+X liquify is a separate handler): Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z undo-redo, **Ctrl+J duplicate**, **Ctrl+D deselect**, Ctrl+] / Ctrl+[ forward/back (+Shift = to front/back via `moveOrder(dir, toEnd)`, using `e.code` because Shift changes `e.key`), Ctrl+S → PNG, Ctrl+Shift+S → JPEG, Ctrl+O → image picker (these three work even while typing and call `preventDefault`), Ctrl+; / Ctrl+' → 안내선, Ctrl+/ → 잠금; plain keys (skipped while typing/editing/confirm dialog): V 이동·크기, C 자르기, B 그리기(펜), E 지우개, T focus `#newText`, [ / ] pen or eraser size ±5 (draw tool), 0–9 → 불투명도 10–90% / 100% of a selected text/shape, Enter/Esc → crop apply/cancel (skipped when a button is focused), arrow keys nudge. Browser-reserved combos (Ctrl+N/T/W, Ctrl+Shift+N) are not used. Button tooltips list the shortcuts.
- **Drag performance.** While dragging/resizing, the `interacting` flag makes `render(..., fast=true)` use `previewOf(p, pw)`, a cached downscaled canvas (filter baked in, keyed by canvas identity + filter + width); dragging calls rAF-throttled `draw()`. The final `paint()` on release uses the original, so export diff stays 0. `dropPrev(p)` invalidates the cache (called from `pushHist`/`endStroke`). Keep `off`'s 2D context created without `willReadFrequently` and resize `off`/`cv` only when dimensions change.
- **Text layout** (`drawItem`): `engine === 'after'` applies wrapping (`wrapLines`), font-size clamp, shrink-to-fit vertically, and clamping into a 4% safe margin (`MARGIN`). `'before'` is a raw baseline engine kept for comparison. Inline editing uses the `#editor-input` textarea overlay while `state.editing` is set (that item is skipped in `render`).
- **사진 보정 target**: the 이미지 panel (`#imgPanel`) is always visible; controls that need a photo (크기 slider, 사진 도구 tabs/buttons, 틀에 꽉 채우기, 회전·반전 — marked `.needphoto`) are dimmed and disabled while nothing image-like is selected (`syncUI`, class `nophoto`). The 사진 보정 presets/sliders act on `adjOwner()`: the selected photo's `adj`, or, with no photo selected, the global `state.adj` which `render` applies to the *whole composite* (photos, template, texts, shapes) through `ctx.filter` (`gTmp` copy; the black preview frame is drawn after the filter so blur does not bleed into the exported interior; `state.adj = null` = off). Preset thumbnails for the global target come from `globalSample()` (a render with `adj: null`) and are refreshed 600ms after the preview settles (`scheduleGlobalThumbs`). `state.adj` is part of `snapDoc`/`docKey`/`restoreDoc` (undoable); "초기화" sets it back to null.
- **사진 투명도**: `#pOp` (under 선택한 사진 크기; always enabled) sets `photo.pclr` (0 = as is, 100 = invisible; drawn with `ctx.globalAlpha` in `render`) for the selected photo, or — with nothing image-like selected — `state.clear`, which the final whole-preview pass in `render` (same pass as the global 사진 보정, `useP`) draws with that alpha over the background color. Both are in `snapDoc`/`docKey`/`restoreDoc`.
- **누끼 (cut-out)** tool (`tool === 'cut'`, tab "누끼", hidden for blank drawings, rotated photos are fine via `unrotPt`; `cut` state object, `#cutOpts`): modes — 색 지우기 (`wandCut`: flood fill or global match by RGB distance ≤ tol, sets alpha 0, optional `softenAlpha` edge feather that only fades the inner side), 지우개/되살리기 (`cutStamp`: `destination-out` radial mask / redraw from `p.orig`, stroke via `stroke.cut`), 올가미 (`lasso.pts` in preview coordinates drawn in an SVG overlay `#lassoSvg`; `closeLasso` clips outside or cuts inside; finish by clicking the red first point, double-click, Enter or the 선택 완료 button; Esc cancels). Every operation does `pushHist` first (undo via 이전/Ctrl+Z) and ensures `p.orig` exists so 되살리기 returns to the pre-cut look. Shortcuts W (색 지우기) / L (올가미); [ ] resize the eraser. Export still flattens onto the background color/template (no transparent PNG).
- **Photo state**: `{id, canvas, w, h, x, y, scale, name, adj, orig, hist, base, prev, ...}`.
  - `adj = {br, ct, sa, wm, bl}` (밝기/대비/채도/따뜻함/흐림) applied through `ctx.filter` built by `adjFilter` (not supported in Safari); `PRESETS` are the quick looks. "초기화" in that panel resets `adj`.
  - Active tool is the global `tool` (`'move'|'crop'|'brush'|'liquify'`) set via `setTool()`; `drawSel` hides the selection box unless `tool==='move'`.
  - **Crop**: pixel crop on `canvas` and `orig`, ratio options (free/1:1/4:5/9:16/16:9), draggable `cropBox` with 8 handles.
  - **그리기** (internal tool key still `'brush'`; formerly 붓 보정, whose 밝게/어둡게/부드럽게 modes were removed): freehand drawing on the selected photo's pixels. Modes (`brush.mode`): `pen` — `drawSeg()` strokes a round-capped line in `brush.color` (`#drawColor` + swatches) with diameter `brush.size` (% of canvas width; `#brushSize` 1–100 → 0.2–20%); `erase` — own size `brush.eraseSize` (`#eraseSize`, shown instead of the 굵기 slider; `brushR()` picks it), clips circles and redraws `orig` (the photo before the first stroke, cloned at the first stroke) over the stroke. `syncBrushUI` shows the color + 굵기 boxes for pen and the 지우개 크기 box for erase. "빈 그림판 추가" (`#newCanvas` in the 불러오기 menu, or "+ 새 그림" `#newCanvas2` in 사진 도구) → `addBlankCanvas()` adds a transparent photo (`blank: true`, named "그림 N"; any number of them can exist, each is its own drawing — `renderLayerList` shows chips in `#layerList` to pick which one to draw on; `#layerName` renames the selected drawing (≤12 chars, empty → '그림', not part of undo) and is focused+selected right after adding one, and `hit()` only picks a blank layer where it has non-transparent pixels near the pointer (`blankHit`), so empty areas fall through to what's below) the size of the frame interior and switches to this tool; for blank photos `#adjBox` gets `.blankMode`, which hides every `.std-only` element (자르기/터치 보정 tabs, 틀에 꽉 채우기, 회전·반전, 사진 보정 presets and the 밝기/대비/채도/따뜻함 sliders), leaving 선택한 사진 크기, 이전/초기화, 이동·크기/그리기, and the 흐림 효과 slider (Ctrl+Shift+X is refused for them). Undo = "이전"/Ctrl+Z via `pushHist`.
  - **터치 보정** (Photoshop-style liquify, Ctrl+Shift+X): `liqStep()` warps via `getImageData`/`putImageData` with smoothstep falloff; modes 터치 보정(push)/부풀리기/오므리기; bloat/pucker repeat on a 40ms interval while held. Brush and liquify share `brushDown/brushMove/endStroke`.
  - **History**: `pushHist` snapshots before each crop/stroke/reset (max 12, `hist`); Ctrl+Z / the "이전" button (`undoAny`) undoes one step (it picks between this pixel history and the document history, see below); `base` is the first snapshot and "초기화" (photo tools) restores it (itself undoable). When undo pops `p.base`, clone it so later strokes can't corrupt it.
- **Dock menus**: the glass dock has "저장하기" (`#saveBtn` → `#saveMenu`: PNG로 저장하기 `#saveAsPng`, JPEG로 저장하기 `#saveAsJpg`, 템플릿 내보내기 (JSON) `#tplExport`), "불러오기" (`#loadBtn` → `#loadMenu`: 이미지 불러오기 `#loadImg` → opens the hidden `#file` input, 템플릿 가져오기 (JSON) `#tplImport` → hidden `#tplFile`, 사진 삭제 `#clearImg`) and a separate "안내선" button (`#guideBtn`, toggles `#guide.on` and its `.on` ring). `dockMenus`/`closeMenus` handle open/close (one at a time; closes on outside click, Esc, or choosing an item). The hidden file inputs live in the dock (not inside `<li>`, to avoid click re-entry). Photos can also be dropped onto the preview (`cw` drop handler). The 이미지 panel (`#imgPanel`, holding 사진 도구 and `#imgMsg`) is hidden unless a photo is selected or a rejected-file message is showing (`syncUI`).
- **Page layout**: `.grid` has three areas — `aside.side` (도형·스티커 and 템플릿 panels, left, sticky with its own scroll when tall), `.window` (preview, center), `aside.main` (이미지 and 문구 panels, right). Under 1250px the side column drops below the preview (areas "preview main" / "side main"), under 900px everything stacks (preview, main, side). Panel IDs are unchanged, so no JS depends on the column.
- **Sticky preview**: `.window` (the preview) is `position: sticky; top: 26px` so it follows the page while scrolling the right-hand panels (`.grid` already has `align-items:start`). It is switched off (`.nosticky`, set in `syncUI`) in free ratio — the canvas can be taller than the screen and the free-ratio center-compensation uses `window.scrollBy`, which a pinned window would defeat — and under 900px width where the grid collapses to one column.
- **Window ✕ button** (`#closeSite` in `.wbar`): calls `window.close()`; browsers only allow that for script-opened tabs, so it falls back to `location.replace('about:blank')` after 150ms. It first asks via the shared confirm dialog (`confirmDelete(msg, onOk, title, okLabel)` → "닫기" / 취소 / 닫기); nothing persists across reloads, so unsaved work is lost.
- **Text deletion**: the "텍스트 삭제" button opens the custom `#dlg` confirm (`confirmDelete(msg, onOk)`; Esc/outside click cancels). Keyboard Delete/Backspace deletes immediately without confirmation — intentional, leave it.
- **Input validation** goes through `setParam` (bounds in `BOUNDS`, `MAX_TEXT`), which rejects bad values and keeps the previous ones with a message in `#textMsg` (shown right under the `#newText` input). `loadFile` validates by magic bytes (`sniff`), not extension; rejects >20MB / empty / non-PNG-JPEG / corrupt files with a visible reason, keeps existing work, and re-encodes via canvas so EXIF/metadata is stripped.
- **Templates** (`TEMPLATES`): each `{id, name, src, y0, y1}` with `y0`/`y1` fractions marking the stretchable middle band. `drawTemplate` keeps top/bottom decoration at full width and stretches only the middle band; if that would squash below 0.5×, it scales the whole image proportionally and centers it. `tplCache` is keyed by `src`. When `state.bg` is null a white background with a black frame (`frameInset`) is drawn, and the frame is cropped off on export. The "템플릿 삭제" button clears `state.bg`.
- **Template JSON import/export**: format `{format:"photo-studio-templates", version:1, templates:[{id,name,src,y0,y1}], selected:id|null}`. `importTemplates` runs `validateTemplates` → loads all images with `Promise.all` → only then commits (`TEMPLATES.splice` + `state.bg`), so any failure (bad syntax, missing field, missing image) leaves existing templates untouched and shows a red `#tplMsg`; success is reported via `toast()` (`#tplMsg:not(.bad)` is hidden). Rules: id `^[a-z0-9_-]{1,32}$` unique; name 1–20 chars; `src` a bare filename (no path/URL/`..`) ending in `.jpg/.jpeg/.png`; `0≤y0<y1≤1` with gap ≥0.05; max 20 templates; file ≤200KB. Imported templates aren't persisted. To add a built-in template, put the image in the folder and add a `TEMPLATES` entry with tuned `y0`/`y1`.

- **Messages** (`.msg` in `index.html`): plain light box, no colored left strip; `.msg.warn::before` prepends a red ⚠ (U+26A0 with the text-presentation selector U+FE0E so CSS `color` applies; the emoji-style ⚠️ would stay yellow) — also in `#toast` when it uses `warn`.
## Gotchas

- Files in this folder have been modified from outside the session more than once (lost edits, stray characters at the start of `index.html` and this file). After editing, check that changes persisted and that the first line of each file is intact.
- Verification so far has been headless (puppeteer-core with real Chrome against `localhost:8000`); real-GPU drag smoothness is unverified.

- **PSD**: `psdBytes` 가 8비트 RGB 레이어 PSD(raw 압축, 레이어마다 투명 영역 잘라냄, 혼합 키·유니코드 이름 `luni` 포함)를 쓰고 Pillow 로 열림·레이어 영역·픽셀을 검증함(Photoshop 으로는 미확인). 가져오기 `parsePsd` 는 8비트 RGB·raw/RLE 만 지원하고 레이어를 사진으로 만든다(숨김 레이어 제외, 레이어 마스크·텍스트·스마트 오브젝트·조정 레이어·효과는 이미지로만 들어오거나 무시됨; ZIP 압축·16비트·CMYK·PSB 는 거부).
- **다중 선택**(`multi.js`): `PSMulti.ids`. Shift/Ctrl+클릭(또는 `#multiMode` 토글 = 터치용)으로 더하고 빼기, 빈 곳 끌기 = 범위 선택, Ctrl+A. 선택 묶음을 끌면 함께 이동(캡처 단계에서 앱의 단일 드래그를 가로챔), 방향키·Ctrl+J·Delete·Esc 도 묶음 전체에 적용. 오른쪽 `#multiBar`: 선택 영역/프레임 기준 정렬 6종, 가로·세로 간격 같게(3개 이상), 복제·잠금·삭제. 다중 선택 중에는 단일용 `#alignBar` 와 `#sel` 핸들이 숨는다.
- **스마트 가이드**: `align.js` 의 `alignSnap` 이 다른 항목의 중심·가장자리(틀을 가득 채운 큰 사진 제외)에도 스냅하고 파란 가이드를 그린다(같은 간격 가이드는 없음).
- **모바일·터치**: 터치 핸들 26px·버튼 키움·좁은 화면에서 제목 숨김. 실기기 터치·두 손가락 확대/축소는 미검증/미지원.
